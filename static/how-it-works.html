DOCUMENT RESEARCH

How it works

DocChat uses a retrieval-augmented generation pipeline: it extracts your document text, retrieves the most relevant chunks, generates an answer from that context, then checks the result.

1

Validate and extract

The API accepts PDF, DOCX, TXT, and Markdown files, limiting each file to 50 MB and an upload to 200 MB. TXT and Markdown are read directly; PDF and DOCX are converted to Markdown with Docling. The extracted Markdown is split at level-one and level-two headings into retrievable chunks.

Chunks are SHA-256 keyed and cached on disk for seven days, so unchanged documents do not need extraction again.

2

Build hybrid retrieval

For a new document set, DocChat creates a Chroma vector store using IBM watsonx ibm/slate-125m-english-rtrvr-v2 embeddings and a BM25 keyword retriever. An ensemble combines their results with 40% BM25 and 60% vector weighting, returning up to 10 vector matches.

The resulting retriever is kept in memory for the browser session and rebuilt when the uploaded files change.

3

Generate from retrieved context

Your question is sent to the hybrid retriever first. The top chunks are joined into context for IBM watsonx Granite ibm/granite-4-h-small, which is instructed to answer only from that context. The answer and uploaded source names are returned to the page.

4

Verify and retry once

A separate Granite pass evaluates whether the answer is supported by the retrieved context, identifies unsupported claims and contradictions, and checks relevance. If the report says Supported: NO or Relevant: NO, DocChat repeats research once; after that it returns the answer and report.

5

Reset the session

The server sets an HTTP-only, same-site session cookie. Selecting New session clears that session’s in-memory retriever and deletes the cookie; restarting the server also clears active sessions.
